## Overview

RAPIDS `v26.08` is the final release that publishes RAPIDS-specific XGBoost conda
packages, including `rapids-xgboost`. Starting with RAPIDS `v26.10`, the `rapids`
metapackage uses XGBoost from `conda-forge` instead.

Historical packages have also changed to allow users to install XGBoost from
`conda-forge`, including when using strict channel priority.

## Impact

### Conda channels

Historical `xgboost`, `libxgboost`, `py-xgboost`, `r-xgboost`, `xgboost-proc`, and
`rapids-xgboost` packages have moved out of the `rapidsai` channel's default `main`
label to `rapidsai/label/legacy-xgboost`. These packages remain available under that
label; they have not been deleted.

With strict channel priority, keeping any `xgboost` packages on the higher-priority
`rapidsai` channel would prevent conda from selecting newer versions from
`conda-forge`. Moving the historical packages removes that restriction.

### Historical RAPIDS releases

The `rapids` metapackages for RAPIDS `v25.12` through `v26.08` have been republished
with build number 1 and unchanged package versions. These builds depend directly
on `xgboost` instead of `rapids-xgboost`, preserving the XGBoost version constraints
but removing the `rapidsai_*` build requirement. With the default channels, these
installations now use XGBoost from `conda-forge` and **no longer include RMM
integration in XGBoost**.

The patched metapackages display an install-time warning with a restoration command
pinned to the installed RAPIDS release. For example, `rapids=26.08` displays:

```text
The xgboost in the rapids metapackage no longer supports RMM integration.
It can be restored by installing:
  conda install -c rapidsai/label/legacy-xgboost "rapids=26.08" "xgboost=*=rapidsai_*"
See https://docs.nvidia.com/datascience/notices/rsn0062/ for more information.
```

The warning omits `-c rapidsai`; include it when running that command to resolve
the explicitly requested `rapids` metapackage.

The original, unpatched build-0 `rapids` metapackages for these releases will be
moved to `rapidsai/label/broken`. Installation specifications pinned to those builds
should be updated to use the patched builds.

The `rapids` metapackages older than `v25.12` have not been patched. Recreating
those environments, or any environment that explicitly requires `rapids-xgboost`,
requires the `legacy-xgboost` label as described below.

## Migration guidance

### Use standard XGBoost packages

Existing users should migrate workloads away from `rapids-xgboost`. Use the
`xgboost` package from `conda-forge`, or the wheels from the Python Package Index
`PyPI`. These packages do not include RAPIDS RMM integration.

In conda installation commands and environment files, replace explicit
`rapids-xgboost` or `rapidsai::xgboost` requirements with `conda-forge::xgboost`,
using a version compatible with your workload.

### Restore legacy RMM-enabled XGBoost

To restore RMM-enabled XGBoost in an existing RAPIDS environment, run:

```shell
conda install -c rapidsai/label/legacy-xgboost "xgboost=*=rapidsai_*"
```

To recreate an environment that depends on historical `rapids-xgboost` packages,
add `-c rapidsai/label/legacy-xgboost` to the installation command, or add
`rapidsai/label/legacy-xgboost` to the environment file's channel list. Place this
label before `conda-forge` when using strict channel priority. If the environment
explicitly requests `rapidsai::xgboost`, replace that requirement with
`rapidsai/label/legacy-xgboost::xgboost`.

The legacy label preserves existing packages; it will not receive new RAPIDS
XGBoost builds. Keep XGBoost, RAPIDS, Python, and CUDA versions compatible when
using these historical packages.
